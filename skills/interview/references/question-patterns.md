# Question patterns

Adapt these examples to the user's topic. A question should include the context needed to answer it; it should not require a particular question tool.

## Discover a broad goal

> What is one real task you want this project to help with? Walk through the input, the result you want, and where the current approach gets in your way.

Use the answer to choose the next questions. A broad goal may need several short rounds.

## Establish a working preference

> This project mixes research notes and finished reports. Should durable task plans live alongside those notes, or should plans stay in the conversation unless a task spans sessions?
>
> - **Conversation by default (Recommended).** Keeps small tasks light; save a plan when continuity needs it.
> - **Save every substantial plan.** Gives collaborators a record, with more files to maintain.

The recommendation is contextual. Reverse it when the user's collaboration needs justify a persistent record.

## Resolve a concrete trade-off

> The report has two credible estimates using different date ranges. Should the headline compare the same period or use each source's latest available figure?
>
> - **Use the same period (Recommended).** Makes comparison clearer, with older data for one source.
> - **Use the latest figures.** Improves recency, but the date difference must be explicit.

## Discuss a draft

> Here are two versions of the introduction. Which better matches the audience, and what should change?

Provide the drafts in a format the user can view. Ask for exact wording approval when the user needs it, such as a publication statement, rather than treating all text as locked copy.

## Record an answer

- Confirmed: compare the same period.
- Assumption: the audience knows the basic terminology.
- Open: whether the shorter appendix is sufficient for reviewers.

Write this into an existing record when useful and authorized. Otherwise return it in conversation.

## Avoid

- Asking the user for facts you can reasonably inspect.
- Options without consequences, or a recommendation without reasons.
- A rigid batch size that conflicts with the conversation or interface.
- Questions about work already authorized, unless the scope has materially changed.
- Treating unrelated answers as approval of a draft, action, or complete plan.
